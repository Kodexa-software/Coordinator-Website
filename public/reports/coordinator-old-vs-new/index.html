How to make it faster and better

In order of payoff for the effort. The savings are estimates from these two runs.

  1. Make the gate trustworthy. Re-run the gate once before creating a fix task. Delete gitignored build outputs (git clean -fdX under gate_cwd, or a pre_gate config) before every gate. Give the fix agent the first error block, not the last 60 lines. ≈65 min and 3 agents saved on the paint run
  2. Run the full gate once. Builders run a fast check (typecheck plus related specs, e.g. jest --findRelatedTests), and only the scheduler runs the full gate after merging. That also frees CPU for parallel builders. most of 133 builder-minutes
  3. Plan for width. The planner states the critical path, and the officer sends back plans that chain tasks needlessly. Split by files so redesign steps run side by side (service history ran T3→T4→T5 in sequence). Aim for 2+ agents busy instead of 1.2–1.35. est. 30–40% of wall clock
  4. Catch visual problems before you do. For UI tasks, take before/after screenshots automatically in Chromium and WebKit at 390 and 1280 px, and have the reviewer check them against the design language. 4 of your 6 follow-up remarks were visual. a review round: ≈55 min of waiting and 3 extra tasks
  5. Right-size the models. Put task audits and code review on Sonnet by default. Keep Opus for plan audits and L-size builds, and use medium effort for the planner on S/M runs. Officer, review and planning are 35–42% of the new runs' cost. est. 15–20% of cost
  6. Cap task size. The planner splits any task estimated over ~45 minutes, and perf profiling becomes its own task with a time budget. Paint T4 alone took 105 minutes and cost 30, 21% of the run. shorter critical path
  7. Guard against overlapping runs. Warn at plan time when another open run touches the same files, and merge the base branch into the run branch after each task so conflicts are small and early. paint T8: 24 min, cost 14
  8. Hand big reading to the briefer. The planner should pass old transcripts and PRs to the Sonnet briefer rather than reading them on Opus. paint planner: cost 19 → est. 6
  9. Keep a metrics line after terminate. Append tokens, minutes per phase, gate times and outcome to .coordinator/metrics.jsonl. The next comparison becomes one command, and the website can publish real numbers (an open roadmap item).
  10. Fix gh --repo origin so pull requests work in repos with an upstream remote.

Items 1–4 alone would likely have cut the paint run from 8.7 h to about 5 h and the service run from 4.3 h to under 3 h. That estimate comes from removing the false gate tasks, the duplicate gates and one review round, and running the chained tasks in parallel.

Method and caveats

377 sessions and 1,308 transcript files under ~/.claude/projects were parsed. Agents were grouped into runs by the run name in their first prompt and by their worktree folder, and matched to pull requests on GitHub. Tokens are de-duplicated per API message.

Active time is time with transcript activity, where any gap over 10 minutes counts as idle. A build or test that ran longer than 10 minutes without output therefore counts as "nobody active".

Caveats. The new paint run was asked to fix PR #19, so it started from the first attempt's work and lessons. That makes the comparison fairer to 0.1 than it looks. Run logs were deleted on terminate, so gate durations are measured inside builders only. Screenshots and perf work in the new runs sit inside "Building". There are only two real ADP runs per version.
